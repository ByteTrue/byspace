# 跨 workspace 的统一编排入口

## 排期：先整理架构，之后再启动

Owner 已确认方向，并要求先跟踪、暂不实施：当前优先整理项目架构，之后再做 Orchestrator。架构整理完成后仍需 Owner 明确要求启动，不自动进入实现。

本 Issue 保存目标、现状线索与待确认边界，不是实施设计。启动时根据整理后的架构重新核对；需要跨多个切片推进时，再决定是否升级为 Epic。当前不为它预建编排服务、通用框架或插件接口。

## 想解决的工作

现在用户需要逐个切换 workspace，查看 agent 的进展、判断哪些会话待处理，再逐一补充要求或回复问题。用户自己承担跨会话的跟进和信息传递。

希望在现有 agent 能力之上增加一个 Orchestrator：用户只需一个入口，它帮助查看、跟进已有会话，在授权范围内回复和推进，把确实需要用户决定的事情汇总过来。用户仍能直接进入原会话接管。

重点是照看已经存在、彼此独立的工作，不只是在接到新任务后创建一批子 agent。

## 目标体验

- 一个入口汇总所选工作范围内的进展、阻塞和待决事项，不要求用户逐个巡视 workspace。
- 能按既定目标处理的跟进，由编排者在授权范围内完成；需要用户决定的，连同必要背景、来源会话和建议一起呈现。
- 用户在统一入口回复后，决定送到正确会话，并继续跟进结果。
- 原 workspace 和会话保持可见、可直接操作；统一入口不替代底层工作空间。
- 执行发生在 daemon 所在机器，手机通过 Web/PWA 做轻量查看、输入和批准，不要求手机运行 agent 或依赖原生客户端。

这条方向从现有 agent 执行与注入工具向上扩展。未来可以接入其他工具，但本 Issue 不定义插件工具箱，也不默认上游插件系统就是工具箱的实现。

## 启动时再确认的范围与护栏

下列是讨论中的候选，启动前需要收束成可验证的设计：

- **观察范围。** 建议先验证同一 daemon 下跨 workspace 的跟进；如何选择纳管会话、是否覆盖多台 daemon，尚未决定。
- **回复权限。** 明确哪些跟进可以自动完成，哪些只能建议或转交用户。会话中的请求不能自行扩大编排者的授权；删除、发布等操作继续遵守项目的确认边界。
- **待办判断。** `idle` 既不等于需要回复，也不等于整个任务完成。结合任务目标和近期内容判断，避免反复发送“继续”。
- **生命周期。** 跟进已有会话不应默认改变父子归属；编排者停止或归档，不应误伤被照看的独立会话。
- **人工接管。** 用户直接处理会话时，避免编排者同时代回；恢复自动跟进的方式待定。
- **恢复与成本。** 待决事项和已发送回复不能只靠模型上下文记忆。需要验证重连、重启后不漏项、不重复代回；优先按事件唤醒、按需读取，不持续轮询全部会话或汇入全部转录。

## 可复用线索：架构整理后重新核对

现有链路是 agent 调用注入工具 → daemon 操作目标会话 → 完成、报错或权限请求回传调用者。它具备编排原语，但不等于已经有全局会话管家。

- [编排能力说明](../../public-docs/orchestration.md)：已有创建 agent、后续指令与异步回传的使用路径。
- [Agent 生命周期](../../docs/agent-lifecycle.md)：父子归属与归档联动，观察关系不能直接套用为父子关系。
- [Daemon 权限](../../docs/permissions.md)：现有权限边界；新增编排入口不能绕过授权。
- `packages/server/src/server/agent/tools/paseo-tools.ts`：已有 workspace/agent 列表、状态、近期内容、发送 prompt 和权限响应工具。agent 调用 `list_agents` 时默认按调用者的 `cwd` 过滤，不能当作全局发现接口。
- `packages/server/src/server/agent/agent-prompt.ts`：已有与创建、后台跟进操作关联的结果回传；不自动订阅全部已存在会话。

这些是复用线索，不要求架构整理保留每一处现有实现，也不据此推导现在需要改哪些包。

## 用真实工作验证

启动时细化以下场景及通过条件；当前不要求执行验证：

1. 同时存在多个 workspace：一个继续执行，一个有可按既定计划处理的问题，一个需要用户作决定。统一入口给出正确分类和来源。
2. 编排者完成已授权跟进，用户一次回复能分别送到正确会话；真正的待决事项不会被自动批准。
3. 用户直接进入原会话接管时，不出现重复或冲突指令。
4. 编排者或连接中断后恢复，不遗漏待办、不重复执行已经发送的回复，也不归档原有独立会话。

核心判断：用户无需逐个切换 workspace 就能了解待处理工作并完成回复，且授权内的跟进确实由编排者完成，而非把所有消息原样搬到一个聊天框。
