# Skill — 问题定义与假设拆解

| 字段     | 内容                    |
| -------- | ----------------------- |
| skill_id | analyst-problem-framing |
| 状态     | ready                   |

## 触发

- 用户提出分析诉求但目标或口径不清晰。

## 输入

- 必需：业务问题、决策场景。
- 可选：时间范围、目标指标、约束条件。

## 执行

1. 将问题拆为 3-5 个可验证子问题。
2. 提取假设与排除项，确认分析边界。
3. 产出统一问题定义并请求确认。

## 输出

- 问题陈述、假设列表、分析边界、成功判据。

## 守则与降级

- 目标不清不进入深度分析。
- 输入缺失时输出“待补信息清单”，不强行推断。

## 依赖分级（MCP / Connector）

- 强依赖：无（可在纯对话下运行）。
- 弱依赖（可增强）：`Search / Research`、`Market Intelligence API（Similarweb / Ahrefs / Semrush）`。

## 能力分层

- **Basic**：仅基于用户提供信息，输出问题定义、假设和边界。
- **Supercharged**：结合外部资料补充行业背景，帮助缩小问题范围并提高假设质量。

## Supercharged 激活条件（必须满足）

- MCP：`WebSearch` 或其他互联网搜索工具（如 `Search / Research`）至少可用 1 项。
- Connector：`Market Intelligence API（Similarweb / Ahrefs / Semrush）` 为可选增强；仅走 WebSearch 路径时不强制。
- 若上述条件不满足：仅输出 Basic 层结果，不输出 Supercharged 结论。

## 分层执行步骤

### Basic

1. 复述业务问题和决策目的，确认“要解决什么”。
2. 拆成 3-5 个可验证子问题。
3. 输出假设、边界、待补信息清单。

### Supercharged

1. 在 Basic 基础上，快速检索同类行业案例与常见指标。
2. 补充“高概率关注维度”（如获客成本、留存、转化）。
3. 给出更聚焦的问题树与优先验证顺序。

## 降级逻辑（非技术化表达）

- 当外部资料暂时取不到时：直接基于现有信息给一版“先可用”的问题框架，并告诉用户“先按这版推进，后续拿到更多背景再精修”。

## Few-shot 示例

- 示例 1（中国大陆 SaaS）  
  输入：“我们是企业服务 SaaS，最近续费率下降，帮我分析。”  
  Basic 输出：续费问题拆解为“客户分层变化 / 产品使用深度 / 价格策略 / 客服响应”4 个子问题。  
  Supercharged 输出：补充同赛道常见续费口径和观察窗口，给出优先验证顺序。
- 示例 2（海外独立站）  
  输入：“Shopify 店铺最近收入掉了，先帮我定义分析问题。”  
  Basic 输出：流量-转化-客单价三段式问题树。  
  Supercharged 输出：补充 Meta/Google 渠道常见波动因素清单。
