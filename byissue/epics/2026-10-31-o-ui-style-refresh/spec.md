# UI 美化：组件样式对齐 shadcn/ui

## 要改变什么

现状：组件样式各处手写，观感廉价。设置页同一张卡片里下拉框、输入框、按钮、分段控件四种底色、四种高度；主页面的侧栏、标签栏、输入框、消息和工具调用卡片各成一套。

目标：所有组件的样式对齐 shadcn/ui，浅色和深色两套；布局不动。讨论过程见 [UI 美化 talk](../../talks/2026-10-31-ui-style-refresh.md)，为什么先在 Expo 版上做见 [Decision](../../decisions/2026-10-31-shadcn-restyle-before-frontend-rewrite.md)。

## 为什么现在做

用户每天长时间看这个界面。这也是前端重写的前置：样式规格先在现有版本里定下来、验证过，重写时直接沿用。

## 当前方案

- **参照：** shadcn/ui 的主题变量和组件源码，快照存在 `design/references/shadcn/`，记录对应的上游版本。数值照源码抄，不凭印象。
- **样板页：** `design/component-sheet.html`。每个组件一行，左边是现状截图，右边是按 shadcn 做的浅色和深色，列出全部状态；用户按编号反馈。定稿后它就是本 Epic 的视觉契约。
- **落地顺序：** 样板页 → 基础设定（`packages/app/src/styles/theme.ts`）→ 基础组件（`components/ui/`、`components/headers/`）→ 组合部件。

## 必须守住

- **布局冻结：** 区域位置和大小、左包右大卡片、面板结构、导航都不动；组件只改颜色、字体、圆角、边框、阴影、图标和内边距。
- **选中态：** 顶部标签栏用下划线；左侧栏选中项保留左侧竖条。
- **字重：** 常用只有两档，正文 400、结构标签 500，不再出现忽粗忽细。层级规则以 `docs/design.md` §3 为准，要改就随实现同步更新这份文档。
- **两套主题同时达标：** 正文对比度不低于 4.5:1，大字不低于 3:1；键盘焦点环可见。
- **只取 token：** 组件不写死颜色、圆角和阴影，重写时可以一一映射到 shadcn 的变量。

## 不选什么

- 不自创风格，不走 impeccable 的新视觉流程。
- 不对着 Linear 截图仿（不开源，数值只能猜）；不用 AGCopilot 的 Ant Design 体系。
- 不先重写再美化。

## 推进视图

| 事项                                                       | 解决什么                                                                            |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| [组件样板页](issues/2026-10-31-o-component-style-sheet.md) | 把每个组件改成什么样定下来，用户逐项确认                                            |
| 基础设定和基础组件（样板页定稿后建）                       | 在 `theme.ts`、`components/ui/`、`components/headers/` 里实现，截图和样板页并排验证 |
| 组合部件（样板页定稿后建，可拆成多项）                     | 按用户的丑组件清单逐项落地，每项单独提交并附前后对比                                |

暂不推进：布局调整、前端重写本身、Diff 页面发糊（渲染问题，另行处理）。

## 关闭条件

样板页里的每一项都已经在 app 里落地，并经用户确认；浅色深色都过了对比度和各状态检查；`docs/design.md` 已同步为新规则。

合并候选：新的 token 和组件规则写进 `docs/design.md`；选中态双指示器这类长期界面约束并入 project spec 的 [Workspace](../../spec/workspace.md)。
