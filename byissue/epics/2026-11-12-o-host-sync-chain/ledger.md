结论取值：`没做`（初始）、`在做`、`做了`（证据写命令和结果、测试名或截图，有 commit 附上）、`不做`（写谁定的）、`不适用`（只用于没有运行时行为的项，写理由）。

- `byspace pair --addr <连不上的 daemon>` 会回退到离线铸 offer，而那条路径过去用 `server.New()` 读身份值，等于把被指向的 home 的 daemon 启动逻辑跑了一遍：不带 `--home` 时解析到生产 `~/.byspace`，写 `chief/`、`cli-credential`，恢复终端会话、尝试起隧道 peer。是 S17 端到端实测时撞上的。已修：离线铸 offer 只读 `server-id` 和 `daemon-keypair.json`，抽出 `server.BuildPairingOfferURLForHome`，CLI 不再构造 Server。守卫测试 `internal/cli/pairing_offer_test.go:TestOfflinePairingOfferDoesNotBootTheHome`（改回 `server.New()` 会让它失败）。生产未受损（PID、config.json mtime、relay 均未变），但这条路径本身是红线。详见 [notes/2026-11-12-cli-pair-offline-offer-boots-the-home.md](../../notes/2026-11-12-cli-pair-offline-offer-boots-the-home.md)。
- 直连主机密码丢失（D 单元引入）：`rememberPasswords` 用原始 endpoint 字符串匹配，用户输入的 `localhost` 与 daemon 上报的 `127.0.0.1` 拼写不同，副本回来后密码对不上被丢弃。已修：改用 `normalizeLoopbackToLocalhost(normalizeHostPort(...))` 规范化。回归测试 `web/src/core/runtime/host-replica.test.ts:keeps the password when the endpoint spelling differs`。浏览器实测确认修复前后 `hasPassword` 从 false 变 true。

## 三方复查后的修复（2026-11-13）

对抗性复查对 F 单元的授权模型做了可复现探针，正确性复查和过度设计复查各自独立看了一遍。下面这些是复查后又改的，全部带测试或外部实测。

- **relay 密码闸门只管文本帧**（P0，已修）。二进制帧在鉴权之前就进 `handleBinaryFrame`，未鉴权的 relay socket 能开终端、传文件。闸门移到分叉之前：什么都没证明的 socket 直接丢，只证明挑战密钥的对端 daemon 只允许隧道 opcode。外部验证见 `scripts/e2e-relay-client-check.mjs` 的 `terminals` 计数。
- **未鉴权的 relay socket 收广播**（P0，已修）。relay 路径传 `greeted=true`，socket 一进 `s.clients` 就是广播收件人。改为初始未握手，证明密码后升级；对端 daemon 保持未握手并豁免 hello 超时。
- **隧道流可被别的 peer 劫持**（P0，已修）。授权只检查 `OpcodeOpen`，`OpcodeDataUpstream` / `OpcodeResume` 按 `TunnelID` 直接路由。`targetStream` 现在记 `ownerKey`，开流之后所有帧必须来自同一 peer。测试 `TestTargetStreamOwnerRejectsOtherPeers`。
- **TS 客户端从不回应 e2ee 挑战**（P0，已修）。Go 客户端会回应，所以 Go 测试全绿；浏览器经 relay 时每一帧都被静默丢弃。`encrypted-channel.ts` 在 flush 之前先回挑战帧。笔记 `2026-11-13-ts-relay-client-never-answered-the-e2ee-challenge.md`。
- **跨 daemon 同步没有发起方**（S5，已修）。改成浏览器当载体：`pullReplica` 把本浏览器从别的 daemon 拿到的 records 一起提交，`pushReplica` 只推差异，`host-runtime.ts` 在任一支持 `hostSync` 的 daemon 上线时交换、写主机时推给所有在线 daemon。
- **删除主机复活**（S19，已修）。差异比较对「副本有、浏览器无」的 id 发 `delete:true`，带墓碑的记录永不重发。一次性导入标记 `IMPORTED_FLAG` 因此删掉：首次交换副本为空，所有本机主机天然是 upsert。
- **监听地址是假控件**（S16，已修）。`listenHost` 从 schema 一路接到 `net.Listen`，回环地址不发（旧 daemon 语义不变），`ForwardState.ListenHost` 回读。
- **`sinkPermissions` 泄漏**（已修）。连接关闭时没从 map 删除，每次 relay 认证写一条永不清理。
- **`createTunnelFromSelection` 两个死参数**（已修）。`password` 和 `offerUrl` 从未被读，删掉。
- **`normalizeEndpoint` 两份重复**（已修）。提到 `packages/protocol/src/daemon-endpoints.ts`，四处调用点共用。

未改的一项：`kind:"rule"` 副本记录目前没有读取方（隧道列表由各主机实时的 `tunnel.list` 聚合而成）。规格把「隧道规则的展示信息」列为同步内容，所以保留写入，等一个真正读它的界面；如果决定不做展示，这条写入和 `spec/connection.md` 的对应句子要一起删。
