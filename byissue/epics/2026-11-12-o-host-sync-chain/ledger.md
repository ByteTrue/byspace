# 台账：主机列表与隧道规则同步

接着做或改这张表之前，先读同目录 `spec.md` 的「当前方案」「必须守住」「不选什么」。

拆分来源：没有对照物的新功能。逐句拆用户 2026-11-12 在对话里的要求（U 开头），再加上 `spec.md` 关闭条件和当前方案里的验收点（S 开头）。

接续点（2026-11-12）：A 单元 daemon 侧完成；F 单元的密钥认证穿刺完成，结论是需要每次会话挑战。下一步建议从 B 单元开始：读代码发现 relay 路径完全不校验密码，客户端还把密码明文放在发往 relay 的子协议里（见 spec「前提」）。`go test ./...` 里 `internal/selfupdate` 的 `TestEnsureBundleCLISymlinkLinksAndRespectsStandaloneCopyUnlessForced` 在干净的 HEAD 上同样失败（Windows 建符号链接失败），与本 epic 无关。

结论取值：`没做`（初始）、`在做`、`做了`（证据写命令和结果、测试名或截图，有 commit 附上）、`不做`（写谁定的）、`不适用`（只用于没有运行时行为的项，写理由）。

## 单元

- **A 副本与合并**：daemon 存副本、逐条合并、删除标记、大小上限、同步 RPC 与能力声明。
- **B 远程连接密码前提**。
- **C 同一台机器上的前端共用一份**，含浏览器旧列表导入。
- **D 客户端**：全量列表、按台输入密码、记住密码、主机公钥校验。
- **E daemon 加入和移除**：设备页、最后在线时间、`byspace devices`。
- **F 隧道**：daemon 密钥认证、目标端本地授权、双向规则、`/tunnels` 规则 UI、`tunnels.json` 迁移。
- **G 回写**：`spec/connection.md`、`docs/architecture.md`、`docs/permissions.md`。
