# 其余页面：设置、主机和配对、项目、历史、定时任务、隧道、欢迎页、全局弹窗

## 目标与范围

新前端里剩下的占位页面和占位弹窗全部换成旧版的实现，对照基线是旧版 8081 的实际行为。从这些路由和弹窗能走到的依赖 React Native 界面的文件约 66 个、2.2 万行。分批做，每批一个提交：

1. **设置框架和应用设置**：设置页本身（左侧分区列表、主机选择、右侧内容卡片，手机上是列表加详情）、通用、外观、通知、关于（版本、更新说明、诊断、已连接主机、社区链接），以及关于页打开的更新说明和诊断弹窗。桌面客户端（Wails）里额外显示的版本更新、命令行工具、配置目录这些行一起做。
2. **主机设置**：主机（外观、网络、后台服务、默认 shell、配对设备、移除主机）、连接（连接列表、添加主机的几种方式、粘贴配对链接）、Agent（提供方列表、提供方设置面板、终端配置、标题生成、技能）、用量。提供方设置面板同时是输入框模型选择里齿轮按钮打开的那个，第 3 步漏了，这批一起挂上。
3. **项目**：项目列表、项目设置、编辑项目、工作区标签，以及侧栏「Add project」打开的添加项目流程。
4. **历史、打开项目、欢迎页、扫码配对、导入会话**。
5. **定时任务、隧道**。

动手前先读旧版对应文件；界面用 shadcn 组件重写，逻辑用共享代码，大文件用 `web/scripts/port/` 的脚本从旧版生成；共享模块里引到 React Native 界面的，在 `web/src/overrides/` 覆盖，对外接口不变。做完后新前端里不再有 `PendingPage`、`PlaceholderPage`、`PendingDialog`。

## 验证

- 每批和旧版 8081 并排截图对照，浅色深色、桌面手机，挑出来的放 `screenshots/web-step4/`，全部对照截图放 `screenshots/对照全集/`。
- 每批涉及的操作在浏览器里逐项做一遍（改设置后刷新还在、增删改真的生效），结果写进执行记录。
- 用前端重写的操作脚本收集客户端「Message validation failed」告警，新出现的 daemon 问题记下并修。
- 关键元素带上旧版的 `data-testid`。
- `npm run typecheck`、`npm run lint`、`npm run format:check` 通过。

**有意和旧版不同**

- 下拉框里悬停和键盘选中的行有灰底（muted）。旧版用 `surface1`，浅色主题下就是白色，和下拉框底色一样，键盘上下选时看不出选中了哪一行。

- 系统提示词编辑框按 Reset 后显示重置后的内容。旧版的编辑框只在打开时取一次值，Reset 后框里还是改过的文字，Save 却已经变灰。
- 新建标签的输入框一打开就获得焦点。旧版代码也要求自动聚焦，但它的菜单在网页上没聚焦成功。
- 标签颜色在浅色主题下用浅色主题那套颜色，原因同第 3 步记录的配置颜色色块（旧版浅色主题实际画的是深色主题的颜色）。

**发现的 daemon 问题**

- 重命名或删除标签后，用到这个标签的工作区不会收到更新，侧栏上的标签当场消失、刷新才回来（旧版新版一样）。第 3 批已修，见下面第 3 批的「顺带修的 daemon 问题」。

**没验到的**

- 多主机项目的移除弹窗：开发版只有一台主机，弹不出来，只按旧版移植并过了类型检查。
- 远程 SSH 添加主机的表单：旧版的选方式里没有入口，新版同样没有。
- 后台服务、重启、移除主机、移除连接只验到确认框能弹出和取消，没有真的执行（会影响开发版 daemon）。
- 配对设备的二维码没有用手机扫；真实提供方的安装没有点（只验了列表和搜索）；用量页只看了开发版里有的提供方。
- 手机上弹出键盘时面板被推到键盘上方，需要真机。

- 调色板：Tailwind v4 的 red、green、blue、amber 等颜色是 oklch，和旧版 `theme.ts` 用的 Tailwind v3 十六进制值不一样（比如错误文字的 `text-red-300`）。`web/src/index.css` 的 `@theme` 改用旧版调色板的数值，旧版没有的色阶保留 Tailwind 的。
- Combobox（项目、对端这类可搜索的下拉框）：底色用页面底色（旧版 `surface0`，深色主题下比 shadcn 的 popover 色深一档），搜索行 42px 高；深色主题下选中、悬停、按下的行用旧版的 `surface1`。浅色主题仍是第 2 批定的灰底。
- 开关：放在表单字段里时贴左，同旧版；之前居中。
- 设置区块标题：右边的控件多、手机上放不下时，压缩标题，右边按钮不动，同旧版；之前按钮会被挤出去几像素。
- 工作区的状态卡片（连接中、主机离线、已归档、不可用）：标题和说明的行高改成 normal，同旧版；之前每行高 2px，按钮低 2px。这是第 3 步第 1 批漏的。

**有意和旧版不同**

- 隧道的允许端口输入框占满一行。旧版本来也要占满（`portInput: flex 1`），但这个样式在网页上没生效，输入框只有 100px 左右宽，连自己的占位文字都显示不全。
- 隧道行和允许端口里的删除图标在按钮里垂直居中；旧版比中线高 2px。

**发现的 daemon 问题**

- agent id：Go 的格式是 `agt_` 加 16 位十六进制，Node 是 UUID，协议的定时任务 schema 按 GUID 校验运行记录里的 agent id。跑过一次的定时任务，编辑、立即运行、查看的回包都被客户端拒收；目标是 Go 建的 agent 的心跳任务会让整个列表显示「Unable to load schedules」。已修：新建的 agent 用 UUID v4（`internal/server/server.go`），补了测试，`npm run audit` 通过（浏览器那一步用 bsk 驱动你的浏览器，没跑），开发版 daemon 已换新二进制；实测新建的 Mock agent 的 id 是 UUID，旧版新版的历史都能列出、没有校验报错。已有的 `agt_` agent 不变。
- 定时任务的执行部分没有从 Node 移植：不按时运行（只有「立即运行」会跑）、新 agent 类任务写死用 pi（忽略配置的提供方和模型）、跑完把项目的主工作区归档。单独开了事项 [定时任务执行层移植](../../../issues/2026-11-01-x-schedule-runner-port.md)。测试时旧版点过一次「立即运行」，开发版 zz-diff-repo 的主工作区因此被归档，已经用上面的 Unarchive 恢复。

**没验到的**

- 心跳任务（目标是一个已有 agent）的列表和只读目标：开发版没有这种任务，新建要从 agent 里发起，没做。
- 添加隧道时选已配对的主机：开发版只有一台主机，列表里只有「粘贴配对链接」。
- 真正连通的隧道：需要第二台 daemon，状态只看到 Disconnected、Paused 和 Error。
- 某台主机加载定时任务失败时的提示条。

### 第 4 步收尾：键盘、悬停和样式对账（2026-11-02）

第 5 批发现焦点框、圆角、键盘这类差异像素比对看不出来，所以第 4 步收尾时对整个新前端做了一轮对账，不只看第 4 步的页面。脚本和原始输出在 `screenshots/对照全集/_脚本/` 和 `screenshots/对照全集/步骤4-收尾对账/`。

**怎么比的**（都是旧版 8081 和新版 8082 并排，同一个开发版 daemon）

- Tab 扫描（`probe-tab-sweep.js`）：16 个页面（首页、设置各分区、主机设置四页、项目列表和项目设置、历史、定时任务、隧道、新建工作区、工作区），从页面顶部按 Tab 走完所有停留点，比停留点的顺序和焦点样式（outline、阴影、圆角），浅色深色各一遍，每遍约 490 个停留点。另外单独扫了打开文件栏后的工作区（Changes 和 Files 两个页签）。
- 悬停颜色（`probe-hover-colors.js`）：上面的页面加工作区，逐个按钮比静止和悬停时的底色和图标颜色，浅色深色。
- 计算样式（`probe-style-parity.js`）：按 `data-testid` 比尺寸、圆角、底色、边框、内边距、文字，桌面和手机。这次补上了工作区（之前进不去：直接打开工作区地址会落到首页，改成在应用内跳转）。
- 文字（`probe-text-boxes.js`）：按文字内容匹配页面上所有可见文字，比行框高度和中心位置，桌面和手机。
- 圆角（`probe-radius-boxes.js`）：按位置和尺寸匹配所有带圆角的元素，比圆角，桌面和手机。
- 像素（`shot-parity.js`）：修完后重拍工作区、打开文件栏的工作区、新建工作区，浅色深色。

**改了什么**

- 焦点：改之前几乎每个停留点都不一样（比如通用设置 15 个停留点 15 处不同），开关完全没有焦点框。原因是 40 多处控件自己画 2px 的环，shadcn 按钮是渐显的 3px 环，盖掉了旧版 Pressable 的全局焦点框（3px、50% 灰、跟着元素的圆角）。改回全局焦点框；文本输入框保留自己的环，同旧版；旧版标题栏图标按钮和侧栏菜单按钮没有焦点框，新版也去掉。另有十几处行（文件树，Changes 树的文件和文件夹，提交列表，PR 面板的标题、检查和活动，GitLab 的 PR 行，技能选择，安装脚本日志的行，输入框上方任务条展开后的行）用键盘聚焦时只填底色或什么都不显示，改成全局焦点框，同旧版。
- 提示气泡：鼠标移到气泡上时气泡不关，还挡住下面的点击。项目路径提示正好盖住项目下第一个工作区，鼠标从项目行往下移时第一下点不到这个工作区。现在离开触发元素就关，而且不接收鼠标，同旧版。
- 侧栏悬停才出现的「+」（新建工作区）和工作区的 ⋯ 不再是 Tab 停留点，同旧版（旧版不悬停时不可点）。
- 圆角：`rounded-2xl` 18→16px（输入框上的模型、思考、角色选择器，新建工作区页的几个选择器）；信息图标、文档链接、侧栏底部的图标按钮改成直角（旧版 0，影响焦点框的形状）；设置页返回工作区那一行 6→8px，标签的关闭按钮 6→4px，文件栏排序按钮 8→6px，开发版标签 6→4px，手机上侧栏菜单按钮 10→8px。
- 尺寸：标签宽度改用 offsetWidth 量文字（旧版 react-native-web 的 onLayout 就是它），之前用小数宽度向上取整，标签常比旧版宽 1px；工作区标签栏的新建标签按钮 24→28px；分屏菜单离右边 6→3px，标签区因此宽回 3px。
- 行高：旧版没设行高的文字是 normal（14px 字 18px 行），几处手写的地方用了 `text-sm`（20px 行）：页面标题、工作区标题旁的项目名、手机上的标签切换、新建工作区页的标题（它下面的内容因此低了 1px）。Commit 按钮的文字是 21px 行，同旧版。
- 文件栏 Files、Changes 页签下的分隔线：改之前当前页签的 2px 下划线盖住分隔线，现在分隔线在上面，下划线露出 1px，同旧版。
- 项目首字母图标：字母自己一个行框居中，同旧版；之前字母高半个像素。
- 模型列表的行：深色主题下悬停、按下用旧版的 `surface1`；浅色主题保留灰底，同第 2 批的下拉框。

**结果**：Tab 扫描除了下面的有意差异，16 个页面浅色深色都没有不同；悬停颜色、计算样式、文字位置剩下的都是结构差异（下面列出），不影响显示。

**有意和旧版不同**

- 侧栏顶部是 Search、Schedules、Tunnels 三行（第 3 步改的），所以比旧版多 3 个 Tab 停留点、少 1 个（BySpace 菜单）。
- 侧栏调宽的拖动把手不是 Tab 停留点。旧版能用 Tab 聚焦它，但没有键盘操作，聚焦了也做不了什么。
- 点按钮后提示气泡关掉（第 3 步第 6 批改的），旧版会一直显示到鼠标离开。
- 输入框右下角的上下文用量圈从 12 点钟方向开始。旧版代码里也是转 -90° 从 12 点开始，但这个旋转在网页上没生效，实际从 3 点开始。

**剩下的差异**（确认过不影响显示）

- 行高：单行文字放在固定高度、居中的行里时（侧栏的项目和工作区、设置导航、标签、输入框上的选择器），新版很多是 20px 行框，旧版 18px，文字位置相同。文字位置扫描里除了上面改的，没有别的偏移。
- 结构：旧版工作区的 ⋯ 在行按钮里面，新版和行按钮并列；按钮有透明的 1px 边框；圆形按钮 9999px 和无穷大的半径；隐藏元素的透明度写在外层还是元素上。

**没验到的**

- 按 Enter、空格：只验了新版不是原生按钮的停留点（服务商行、定时任务行、侧栏项目行），没有对每个停留点逐个按 Enter 比结果。有删除、卸载这类按钮，在开发版上按下去会改数据。
- 弹窗、菜单、表单打开以后的 Tab 顺序和焦点样式；终端、Diff、PR、代码审查这些面板里只扫了文件栏的两个页签。
