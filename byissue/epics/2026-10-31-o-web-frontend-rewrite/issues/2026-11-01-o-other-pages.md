# 其余页面：设置、主机和配对、项目、历史、定时任务、隧道、欢迎页、全局弹窗

## 目标与范围

新前端里剩下的占位页面和占位弹窗全部换成旧版的实现，对照基线是旧版 8081 的实际行为。从这些路由和弹窗能走到的依赖 React Native 界面的文件约 66 个、2.2 万行。分批做，每批一个提交：

1. **设置框架和应用设置**：设置页本身（左侧分区列表、主机选择、右侧内容卡片，手机上是列表加详情）、通用、外观、通知、关于（版本、更新说明、诊断、已连接主机、社区链接），以及关于页打开的更新说明和诊断弹窗。桌面客户端（Wails）里额外显示的版本更新、命令行工具、配置目录这些行一起做。
2. **主机设置**：主机（外观、网络、后台服务、默认 shell、配对设备、移除主机）、连接（连接列表、添加主机的几种方式、粘贴配对链接）、Agent（提供方列表、提供方设置面板、终端配置、标题生成、技能）、用量。提供方设置面板同时是输入框模型选择里齿轮按钮打开的那个，第 3 步漏了，这批一起挂上。
3. **项目**：项目列表、项目设置、编辑项目、工作区标签，以及侧栏「Add project」打开的添加项目流程。
4. **历史、打开项目、欢迎页、扫码配对、导入会话**。
5. **定时任务、隧道**。

动手前先读旧版对应文件；界面用 shadcn 组件重写，逻辑用共享代码，大文件用 `web/scripts/port/` 的脚本从旧版生成；共享模块里引到 React Native 界面的，在 `web/src/overrides/` 覆盖，对外接口不变。做完后新前端里不再有 `PendingPage`、`PlaceholderPage`、`PendingDialog`。

## 验证

- 每批和旧版 8081 并排截图对照，浅色深色、桌面手机，挑出来的放 `screenshots/web-step4/`，全部对照截图放 `screenshots/对照全集/`。
- 每批涉及的操作在浏览器里逐项做一遍（改设置后刷新还在、增删改真的生效），结果写进执行记录。
- 用前端重写的操作脚本收集客户端「Message validation failed」告警，新出现的 daemon 问题记下并修。
- 关键元素带上旧版的 `data-testid`。
- `npm run typecheck`、`npm run lint`、`npm run format:check` 通过。

**有意和旧版不同**

- 下拉框里悬停和键盘选中的行有灰底（muted）。旧版用 `surface1`，浅色主题下就是白色，和下拉框底色一样，键盘上下选时看不出选中了哪一行。
- 手机上带自动聚焦输入框的面板（重命名主机、新建终端配置、粘贴配对链接）：旧版打开后整张面板顶到屏幕最上面、背后的页面看不见，原因是浏览器为了把获得焦点的输入框滚进视野，把面板外层滚动了；新版面板停在原来的高度，弹出键盘时由 vaul 把面板推到键盘上方。
- 系统提示词编辑框按 Reset 后显示重置后的内容。旧版的编辑框只在打开时取一次值，Reset 后框里还是改过的文字，Save 却已经变灰。
- 新建标签的输入框一打开就获得焦点。旧版代码也要求自动聚焦，但它的菜单在网页上没聚焦成功。
- 标签颜色在浅色主题下用浅色主题那套颜色，原因同第 3 步记录的配置颜色色块（旧版浅色主题实际画的是深色主题的颜色）。

**发现但没修的 daemon 问题**

- 重命名或删除标签后，用到这个标签的工作区不会收到更新：侧栏上的标签当场消失，刷新才回来（旧版新版一样）。Go 的 `store.UpdateLabel`、`DeleteLabel` 改写了 `workspaces.json`，处理函数却只推了标签目录的帧；Node 在提交后为每个改到的工作区发 upsert。Go 的重命名还缺 Node 的几条校验：标签不存在时报错（Go 会直接新建）、改成另一个已有标签的名字时报错、按归一化后的 key 匹配。已记待办，下次 daemon 快改一起修。

**没验到的**

- 多主机项目的移除弹窗：开发版只有一台主机，弹不出来，只按旧版移植并过了类型检查。
- 远程 SSH 添加主机的表单：旧版的选方式里没有入口，新版同样没有。
- 后台服务、重启、移除主机、移除连接只验到确认框能弹出和取消，没有真的执行（会影响开发版 daemon）。
- 配对设备的二维码没有用手机扫；真实提供方的安装没有点（只验了列表和搜索）；用量页只看了开发版里有的提供方。
- 手机上弹出键盘时面板被推到键盘上方，需要真机。
