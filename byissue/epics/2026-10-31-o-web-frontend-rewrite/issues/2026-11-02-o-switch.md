# 切换：端到端用例对新前端跑通，构建切到 web/，删除 packages/app 和 Expo

## 目标与范围

新前端在浏览器、桌面窗口、Android 客户端和 PWA 里都已和旧版对等（第 1–5 步）。这一步让它成为唯一的前端。分批做：

1. **端到端用例对 `web/` 跑通**：CI 加一组对 `web/dist` 跑的 Playwright 分片，和旧版那组并行；切换前它只作参考，不挡 CI。失败逐个处理：新前端的缺陷修新前端，有意改过的布局或交互（侧栏导航行等，见各批记录的「有意和旧版不同」）改用例。不适用的用例逐个写明原因。
2. **打包体积**：Mermaid 的运行时（3.5 MB，内联整个 Mermaid）改为第一次画图时再加载。只做这一处：剩下最大的是协议的生成校验器（2.8 MB），启动就要用，拆不出去。
3. **构建切到 `web/`**：`scripts/build-daemon-web-ui.mjs` 和 `make build-web` 改为构建 `web/`；`npm run dev` / `dev:app` 起新前端；CI 端到端只对 `web/` 跑；Docker、发版流程、开发文档同步。切完后正式版下次发版就是新前端。
4. **删除 `packages/app` 和 Expo**：先给用户一份删除清单、把删除前的提交推一个远端存档标签，用户确认后再删。`web/` 还在用的非界面模块（状态、daemon 通信、多语言等）搬进 `web/src`，端到端用例搬到 `web/`，删掉 React Native 界面代码、Expo 和 React Native 依赖、只为 React Native Web 存在的文档（`docs/unistyles.md`、`docs/react-compiler.md`、`docs/expo-router.md` 等）；`AGENTS.md`、`docs/development.md`、`docs/architecture.md` 同步。

用户逐页验收穿插在第 1–3 批之间：每批做完给预览地址。

## 验证

- CI 上对 `web/dist` 的 16 个分片全部通过，不适用的用例在执行记录里逐个列出原因。
- 切换后 `make build-full` 产出的二进制、开发版桌面窗口、Android 安装包都是新前端，各打开一次确认。
- `npm run typecheck`、`npm run lint`、`npm run format:check` 通过；动到 Go 时 `npm run audit` 通过。

## 执行记录

### 批 1：端到端用例对 `web/` 跑通（2026-11-03）

CI 加了 `playwright-web`：同一套 16 个分片，`E2E_STATIC_WEB_DIR` 指向 `web/dist`，`continue-on-error`，不挡 CI；`web/**` 的改动也触发浏览器检查。第一次跑新版 16 片有 15 片失败、约 170 条用例失败，旧版全过。本地按文件对新旧两版各跑一遍，失败分三类处理，最后 run 41488948948 新旧各 16 片全部通过。没有用例被判为不适用、也没有跳过。

**新前端的缺陷，改 `web/`**（逐条和旧版行为对齐）：

- 打开 Settings、History、定时任务时工作区保持挂载（`web/src/app/workspace-layer.tsx`），和旧版导航栈一样：终端、滚动位置、草稿都还在，返回不重建。配套一个 `useIsFocused` 替身，被遮住的工作区不再跳转盖住它的页面；路由去掉 transition，刚打开工作区就按快捷键时作用在新工作区上。
- 对话框关闭后焦点回到打开它的元素；sheet 可见的标题就是对话框标题，屏幕阅读器不再读两遍；桌面 sheet 关闭时 160ms 淡出再报 dismiss，保存配置档后立即再打开编辑不再失败。
- 菜单：去掉退出动画和滑入；`transition-none`，缩放不再从中心漂到角上；右键菜单在指针下方 4px、左边对齐指针；在菜单里点右键不再打开外层的右键菜单。
- 图片查看器里按 Escape 只关查看器，不再同时中断后面的 agent（Mermaid 全屏同理）。
- 侧栏收起后不在 Tab 顺序和无障碍树里；行的 ⋯ 不悬停时隐藏；工作区悬停卡片是以脚本列表命名的 menu。
- 下拉框在上层弹出对话框抢走焦点时不关闭；输入框的补全浮层按底边定位、绘制前测量、在手机侧栏之下；模型列表虚拟滚动（`@tanstack/react-virtual`，几百个模型只挂可见行）。
- 主题色改用 sRGB hex（和旧版 `theme.ts` 换算结果一致），界面字号逐档取整；主机徽标颜色落在图标笔画上。
- 其余：标签页悬停提示、Diff 文件头和目录行长按选中、拆分按钮 28px、⌘K 文件搜索出错文案、添加项目流程输入框聚焦、工作区被遮住时打开的标签返回后显示。

**DOM 有意不同，改用例**：每处在用例或 helper 里标 `COMPAT(web-switch)`，删 `packages/app` 时只留 `web/` 分支（`rg "COMPAT\(web-switch"`）。确认对话框从 `window.confirm` 变成页内 AlertDialog（`helpers/confirm-dialog.ts`）；⌘K 的行是 option；菜单外点击（`web/` 没有遮罩元素，`helpers/menu-backdrop.ts`）；bottom sheet 的遮罩和把手选择器；侧栏工作区行是 link；工具调用 shimmer 用 class 不用行内 style；历史加载转圈是 SVG；弹窗打开时输入框的停止按钮在无障碍树外；侧栏导航行（第 2 步有意去掉了「BySpace ⌄」菜单）。

**daemon 缺陷，改 Go**（`cf11b07ba`）：删除 provider 从来没写进 `config.json`（provider 存在 `agents.providers`，删除只改了平铺的那份），下次读配置或重启就回来了；provider 目录重建一秒多，配置改动期间先开始的构建后完成会覆盖新结果并广播，刚加的 provider 半秒后从列表消失。构建按开始顺序编号，被更新的构建或配置改动超过的结果丢弃，和 Node 的 snapshot manager 丢弃旧 generation 一致。

**本机验不了的**：本机没有 `claude` CLI，导入 Claude 会话那一步只能在 CI 验；`archive-tab` 用的是 OpenCode，本机用 mock agent 的副本验了三条用例都过。

### 批 2：打包体积（2026-11-03）

Mermaid 运行时（3.5 MB，整个 Mermaid 内联在 iframe 的 srcDoc 里）改为第一次画图时加载。首屏 JS 由 12.9 MB（gzip 3.3 MB）降到 9.4 MB（gzip 2.3 MB）。剩下最大的是协议的生成校验器（2.8 MB），启动就要用，不拆。

### 批 3：构建切到 `web/`（2026-11-03）

- `npm run build:daemon-web-ui` / `make build-web` 构建 `web/`（先 `build:app-deps`，全新检出也能构建，和原来 Expo 的 `build:web` 一样自带这一步）。`make build-web` 照旧删掉超过 1 MB 的 JS 原文件只嵌 `.br`/`.gz`，路径从 `_expo` 改成 `assets`。
- `public-docs/` 和 changelog 的渲染脚本移到 `scripts/build-public-docs.mjs`，`web/` 的 `build` 末尾调用它；daemon 和 Worker 的 `/docs`、`/changelog.html` 照旧。
- `npm run dev` / `dev:app` 起 Vite（8082）；`npm run dev:expo` 起旧版（8081），删 `packages/app` 时一起删。`byspace.json` 的 app 服务同步。
- CI：端到端只对 `web/dist` 跑，去掉 `playwright-web` 和 Expo 导出；端到端 global setup 默认用 `web/dist`，`E2E_USE_METRO=1` 才跑旧版。
- Deploy App 工作流和 `workers/relay` 的手动部署改为构建 `web/`；Worker 的 assets 指向 `web/dist`。Dockerfile 补 `web/package.json`。
- 文档：`AGENTS.md` 快速开始、`docs/development.md`（开发命令、嵌入构建、Playwright MCP 地址、Web 部署）、`docs/testing.md`（端到端用哪个前端）。

体积：raw 13.29 MiB、gzip 3.31 MiB、brotli 2.87 MiB（原 Expo 版 v0.16.1 时 19.41 / 4.37 / 3.22）；嵌入二进制的部分约 7.4 MiB，`bin/byspace` 19.9 MB。

验证：`make build-full` 的二进制里嵌的是 `web/` 的构建（Go 测试读嵌入的 `index.html` 和被裁掉原文件的大 JS，br / gzip / 不支持压缩的请求都返回 200）；用切换后的产物打 Android 安装包装进模拟器打开，欢迎页正常；开发版桌面窗口第 5 步起就是新前端；本地不带参数跑端到端两组用例走 `web/dist`，16 条通过。Docker 镜像本机没有 Docker 引擎没构建，下次发版的 Docker 工作流会构建。

### 批 4：删除 `packages/app` 和 Expo（2026-11-03）

删除前的提交推了存档标签 `archive/expo-app`（`eab7d2488`），用户确认删除清单后执行。删掉的东西都能从这个标签取回。

- **合并目录**：`packages/app/src` 里新前端打包用到的模块（连同只有类型的文件、所测模块留下的测试与夹具），和 `web/src/overrides` 合成一棵 `web/src/core`，`@/` 只指向它。两边都有的只有 `lib/overlay-root.ts`，合成一个文件。`.web` 后缀去掉。`web/vite.config.ts` 的两层解析、Metro 风格图片 `require`、共享 `public/` 三个过渡插件删掉；状态 favicon 和通知图标改为 `import`，`public/` 搬到 `web/public`。转换脚本生成的文件，头部改为写明来源脚本在存档标签里、现在直接改。
- **单元测试**：`web/vitest.config.ts`（unit 和 browser 两个 project，解析与构建一致），503 个文件、4600+ 条全过。删掉的测试都是测已被网页版替换的 Expo 实现：`svg-root-transform`（React Native SVG 的 transform 解析）、`status-badge.browser`（断言 react-native-web 的行内背景）、`tracks-panel.browser`（渲染 React Native 组件）、`workspace-scripts-button`、`workspace-route-navigation`、`task-list-row`、`tooltip`、`commits-section`、`synced-loader`、`context-menu`（都在 mock 网页版不再用的 React Native 组件）、`unistyles-module-scope`（Unistyles 样式表的模块作用域问题，网页版没有样式表）；`providers-section` 一条行结构断言、`review/surface` 的 gutter 部分、Markdown 链接文本两个已无人引用的文件一并删。改写的：`confirm-dialog`（改测页内对话框）、`providers-snapshot`（去掉 React Native 的 AbortController 变体）。搬过来时测出一处网页版缺陷：改名对话框打开时没有全选原名，已改回旧版行为。
- **端到端**：`e2e/`、`perf/`、Playwright 配置搬到 `web/`；global setup 去掉 Metro 模式；`isWebFrontend` 的分支和 5 处 `COMPAT(web-switch)` 只留 `web/` 一侧，「BySpace ⌄」菜单的 helper 和对新前端跳过的 4 条菜单用例删掉。
- **依赖**：`packages/app` 移出 workspaces，React Native / Expo / Metro / Babel 相关依赖全部去掉。`@react-native-async-storage/async-storage` 的网页版就是 localStorage 外包一层 Promise，换成 `web/src/shims` 里的同样实现，免得把 `react-native` 作为 peer 依赖带回来。新前端实际用到、原来只在 `packages/app` 声明的依赖补进 `web/package.json`，版本对齐删除前的锁文件（xterm 系列锁回 `6.1.0-beta.213` 那组，`js-base64` 锁回 3.7.8）。`patches/` 的 6 个补丁都是 React Native 包的，连同 postinstall 脚本删除；`web/scripts/`（53 个转换脚本）、`scripts/dev-app.mjs`、`npm run dev:expo` 删除。React Compiler 的 10 处 `"use no memo"` 删掉（网页版不跑 React Compiler）。
- **构建守卫**：删除后的第一次构建漏了 `buffer` 依赖。Vite 把 Node 内置名 `buffer` 替换成空模块，只打一条警告、构建照常成功，打开工作区时 `Buffer.from` 报错白屏，端到端两条用例因此失败。补上依赖，并在 `web/vite.config.ts` 加了检查：出现这类警告构建直接失败（拿掉依赖反向验证过会失败）。
- **文档**：删除 `docs/unistyles.md`、`docs/react-compiler.md`、`docs/floating-panels.md`（组合框宽度规则仍然成立，并进 `docs/design.md` §6）；`docs/expo-router.md` 改写为 `docs/routing.md`（工作区层、启动恢复、去工作区不加历史）；`docs/hover.md`、`docs/menus.md`、`docs/mobile-panels.md` 改写成网页版的实现（「目的地不是菜单」一节按第 2 步去掉「BySpace ⌄」的决定改写）；其余 20 份文档里指向 `packages/app` 的路径改到 `web/`，这批之前就已失效的引用（`left-sidebar.tsx`、`sidebar-workspace-list.tsx`、`project-picker-modal.tsx` 等）一并改正，指向被改写文件的行号去掉；`AGENTS.md`（仓库地图、文档表、平台约定、根目录 Vitest 规则）、README 四种语言同步。
- **CI**：第一次推送单元测试 28 个文件失败：合并后的 vitest 配置漏了旧配置里 `@bytetrue/relay` 指向源码的别名（单元测试按 node 条件解析到 `packages/relay/dist`，CI 跑单元测试前不构建 relay），补上（`20cf20a7f`，拿掉 `dist` 本机复现后验证）。第二次推送端到端 16 片有 1 片失败：Diff 画布右键菜单的「Copy」偶发不可用。查明是缺陷，旧版同样有：拖出选区后，只要字体加载完成或视口高度变化，选区就被清掉（清选区的 effect 依赖 `setSelection`，`setSelection` 随绘制函数在字体、视口变化时换身份）。本机重复跑 13 次失败 9 次；修复后同一用例 48 次、Diff 相关 41 条用例全过。
- **代码注释里的 `packages/app`**：`web/src` 里约 530 处注释写着「照 packages/app 的某某」，指的是旧版实现。不逐条改，`AGENTS.md` 仓库地图写明它们指存档标签里的 Expo 版。
- **本机验证**：开发版桌面窗口重开后是删除后的构建（截图核对工作区、文件、输入框）；开发服务器 8082 打开首页、工作区、设置、历史（224 个 agent）、定时任务，控制台无报错。
