# 切换：端到端用例对新前端跑通，构建切到 web/，删除 packages/app 和 Expo

## 目标与范围

新前端在浏览器、桌面窗口、Android 客户端和 PWA 里都已和旧版对等（第 1–5 步）。这一步让它成为唯一的前端。分批做：

1. **端到端用例对 `web/` 跑通**：CI 加一组对 `web/dist` 跑的 Playwright 分片，和旧版那组并行；切换前它只作参考，不挡 CI。失败逐个处理：新前端的缺陷修新前端，有意改过的布局或交互（侧栏导航行等，见各批记录的「有意和旧版不同」）改用例。不适用的用例逐个写明原因。
2. **打包体积**：Mermaid 的运行时（3.5 MB，内联整个 Mermaid）改为第一次画图时再加载。只做这一处：剩下最大的是协议的生成校验器（2.8 MB），启动就要用，拆不出去。
3. **构建切到 `web/`**：`scripts/build-daemon-web-ui.mjs` 和 `make build-web` 改为构建 `web/`；`npm run dev` / `dev:app` 起新前端；CI 端到端只对 `web/` 跑；Docker、发版流程、开发文档同步。切完后正式版下次发版就是新前端。
4. **删除 `packages/app` 和 Expo**：先给用户一份删除清单、把删除前的提交推一个远端存档标签，用户确认后再删。`web/` 还在用的非界面模块（状态、daemon 通信、多语言等）搬进 `web/src`，端到端用例搬到 `web/`，删掉 React Native 界面代码、Expo 和 React Native 依赖、只为 React Native Web 存在的文档（`docs/unistyles.md`、`docs/react-compiler.md`、`docs/expo-router.md` 等）；`AGENTS.md`、`docs/development.md`、`docs/architecture.md` 同步。

用户逐页验收穿插在第 1–3 批之间：每批做完给预览地址。

## 验证

- CI 上对 `web/dist` 的 16 个分片全部通过，不适用的用例在执行记录里逐个列出原因。
- 切换后 `make build-full` 产出的二进制、开发版桌面窗口、Android 安装包都是新前端，各打开一次确认。
- `npm run typecheck`、`npm run lint`、`npm run format:check` 通过；动到 Go 时 `npm run audit` 通过。
