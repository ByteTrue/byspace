# UI 美化 talk

## 开场：想要极简优雅，控件看着廉价

用户想彻底美化 UI，要求找一个以极简优雅著称的产品直接抄风格。最让人觉得档次低的是按钮、输入框这类基础控件（附设置页截图：同一张卡片里下拉框、输入框、按钮、分段控件四种底色、四种高度）。

## 第一轮：Linear 方向，设置页变好看，主页面没跟上

给了 Linear、Vercel Geist/shadcn、macOS 原生、Claude/Raycast 四个参照，用户认可 Linear 方向（「我觉得你选择的 linear 风格挺好的」）。只改了 `styles/theme.ts` 和 `components/ui/` 的一部分：设置页确实变好看了，主页面「差点意思」。

后续调整暴露了几个问题：有的字用 500、有的用 400，看起来忽粗忽细；整体对比度高，看久了不舒服。我还把顶部标签栏改成了胶囊、拿掉了侧栏选中竖条。**纠正，以此为准：顶部标签栏保留下划线选中态，左侧栏保留左侧竖条选中态，两个都要。**

## 第二轮：Claude 风格加前端重写，被否

改成 Claude 暖羊皮纸风格（奶油底、衬线大标题、陶土红强调），同时商定用 Vite + React 重写前端。用户看过预览后评价「丑到爆炸」，Claude 风格作废。

## 第三轮：impeccable 选方向，叫停

用 impeccable 的新视觉流程做了海图、线路图、星图等方向的原型。它的选择页远程打不开，用户叫停，改成直接看 HTML 原型；随后决定全部回退，在新的讨论里重来。这一轮所有改动的备份在 git stash「ui-restyle 2026-10-30: reverted session changes」，只保留了 Web 端「左包右」大卡片的修复（`7e775b73c`）。

## 收束：只改样式，照 shadcn/ui 抄

用户问了两件事：impeccable 对美化有没有用；布局（包括左包右）已经满意，只想美化组件样式和配件、把丑组件换成好看的，自己不是前端工程师，描述不精准，总绕路。

- impeccable：不用它定风格。它的新视觉流程面向从零设计一套新视觉，会把方向推向主题化；它的自动检测在原版和用户嫌丑的那版上都报了 0 个问题；选择页远程用不了。只借用它的易漏项清单（各种状态、焦点框、滚动条、选中文字颜色、对比度）做收尾检查。
- 绕路的根因是没有固定的视觉参照：「极简优雅」没法精确执行，只能猜，用户要等改进 app 才能判断。改成用参照物代替描述。AGCopilot 的组件是 Ant Design 体系，和 Linear 不是一路，不当组件参照。

**已确认：**

1. 布局冻结：区域位置和大小、左包右大卡片、面板结构、导航都不动；只改组件本身的颜色、字体、圆角、边框、阴影、图标和内边距。
2. 唯一组件参照是 shadcn/ui：和用户认可过的 Linear 同一路，组件数值是公开代码，图标和 BySpace 一样用 Lucide，以后重写可以直接用。
3. 浅色和深色一起做。
4. 先做 HTML 样板页：每个组件左边现状、右边按 shadcn 做，全部状态和两套主题，用户按编号反馈；定稿后在现有 `packages/app` 里实现。
5. 美化效果好的话，下一步是前端重写（摆脱 Expo）；这次的样板页和基础设定要能直接带过去。
