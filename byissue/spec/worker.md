# Worker 与项目组

> **读者：** 想知道「我给人提需求，人自己组队把事办了，回来汇报」这条路径**为什么长成这样**，以及后续改动必须守住哪些边界。

BySpace 原本只有**会话**：选 workspace、起 agent、读时间线。agent 短暂、无身份、彼此不知情。worker 域引入第二种对象：**agent 成为长期实体**，多个 worker 组成**项目组**，由一个**协调者**拉人、拆活、派活、汇总，并主动向用户汇报。用户的动作从"逐个操作 agent"变成"给一件事，然后读结果"。

入口是独立路由 `/workers`（自带侧栏，不套工作区外壳）。它与结构化会话、terminal 两条主线**并列而非替代**：两条主线不变，能力复用而界面不耦合。

## 词汇

- **Worker** — 长期存在的 agent 实体，有身份、角色与工作区。一次任务是它的一个 session。
- **项目组** — 多个 worker 在同一项目上协作的容器，**恰好一个协调者**。
- **协调者** — 组里负责拆解、派活、汇总、汇报的那一个。
- **提及即唤醒** — 被点名才会被唤醒；未点名只是可见的上下文。
- **预算** — 一次协作可消耗的公开消息上界。

## 边界与取舍

**「谁负责」由数据库保证，不由应用代码保证。** 一个组恰好一个协调者是一条**部分唯一索引**，不是一句检查。「谁负责」是读的人必须能信的约束，所以两个协调者在 schema 层**不可表示**；应用层的检查只为给出可读错误。同一取舍用于「一个组一个目标」和「一条消息对每个收件人各有一行投递」。

**提及决定唤醒，正文不决定路由。** 路由读结构化的 audience，**从不解析正文** —— 正文里的 `@名字` 只是呈现。解析正文等于让路由依赖散文。

**可见性与唤醒是两个独立问题。** 收窄谁可读不改变是否唤醒。这不是 BySpace 的设计，是照搬参考产品的区分：一条消息可以对全组可见而**不唤醒任何人**。

**预算界的是公开说了多少，不是做成这件事花了多少。** 只有公开消息计数，私密消息免费。

**预算触顶停止的是唤醒，不是沟通。** 超限后不能再唤醒任何人，但仍可发非唤醒消息 —— 必须的生命周期更新不该为省额度而被省掉。触顶的出路是 reopen 一个新预算或让工作停下；**为了让额度够用而调高它，正是额度要防的事**。

**完成是对目标的声明，不是对每个任务的声明。** 目标可以完成而那些被阻塞或退回的任务仍未解决，两者必须能分别表达。

**`blocked` 不必先经过 `submitted`。** 一条失败、或被权限挡住的 run 没有产出；要求它先记下一次并未发生的提交，会让审计流水撒谎。

**技能里的规则是给模型的对话规则，不改 daemon 的裁决。** 技能会要求"建员工前先跟用户确认"，但那条**不阻止命令**，也不改变 daemon 允许什么。真正的边界在权限层：创建 worker 需要比写工作区更高的权限，自批审批在 daemon 层被拒。

**worker 域有自己的数据库。** 主域的 JSON 存储没有迁移框架且每条记录用 Zod 校验；这里需要原子读改写加只追加的历史。分开意味着两边都不用接受对方的持久化规则。

**迁移只自动覆盖增量。** 加表加索引靠 `CREATE ... IF NOT EXISTS` 自己完成；**改已有的列必须写真正的迁移步骤**并留版本行 —— 版本行是这些步骤判断还差什么用的。已经发生过一次（目标文本从组上搬进目标实体），那次的要求是**保留数据**，不是丢弃。

**一个 worker 同时只跑一个任务。** 它只有一个工作区，两个 run 就是同一目录里的两个 session，结果无法干净归属。这条也是"同一份活不会被派两次"的保证。

## 明确不属于这条线

- IM 渠道与配对；知识库；定时任务与自动化触发；WakerFlow 式流程编排；插件与技能市场；云账号与额度；跨设备远程 worker。
- 不引入阿里生态之外的开源项目作为底座；不移植参考产品的 minified 代码。
- 不把 worker 做成唯一入口；不改动或弱化结构化会话与 terminal。

## 已知不足

- 名册与 console 靠"未加载则轮询"而非事件驱动。
- 逐工具裁决有规则与函数，但**尚未接入执行路径**。
- worker 跨任务不积累经验；记忆未做。
- 角色模板的技能文件已入仓，但装配时只用角色三件，技能未接入运行时。
